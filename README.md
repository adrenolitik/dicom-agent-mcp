# dicom-agent-mcp

<!-- mcp-name: io.github.arunmk-ms/dicom-agent-mcp -->

MCP-сервер (Model Context Protocol), предоставляющий ИИ-агентам единый набор инструментов для работы как с **DIMSE**-архивами (C-ECHO, C-FIND, C-GET, C-MOVE, C-STORE), так и с **DICOMweb**-архивами (QIDO-RS, WADO-RS, STOW-RS).

Также включает инструменты для работы с пикселями и геометрией локальных файлов: рендеринг, статистика, измерения, проверки геометрии, многопланарная реконструкция (MPR) и деидентификация. Это инструментальный слой для Темы 3 (Validated Tool Execution). Цикл верификации будет реализован позже; см. [ROADMAP.md](ROADMAP.md).

> **Не для клинического использования.** Это исследовательский каркас. Используйте только с тестовыми или деидентифицированными данными.

## Инструменты

| Инструмент | Узел DIMSE | Узел DICOMweb | Примечания |
|---|---|---|---|
| `list_nodes` | – | – | Перечисляет настроенные узлы; секреты никогда не возвращаются |
| `echo` | C-ECHO | `GET /studies?limit=1` | Проверка связи |
| `search` | C-FIND | QIDO-RS | Уровни: пациент, исследование, серия, экземпляр. Поддерживает маски и диапазоны дат. Страничная навигация использует `offset`/`limit`. QIDO не имеет уровня пациента |
| `get_metadata` | C-FIND (только индексированные атрибуты) | WADO-RS `/metadata` | Возвращает JSON на основе ключевых слов; объёмные данные суммируются |
| `retrieve` | C-GET | WADO-RS | Сохраняет файлы в `storage_dir/<study>/<series>/<sop>.dcm` |
| `move` | C-MOVE | – | Назначение — имя узла или AE title |
| `store` | C-STORE | STOW-RS | Принимает файлы или директории внутри песочницы |
| `transfer` | retrieve + store | retrieve + store | Работает через протоколы (например, PACS → DICOMweb) |
| `list_local_files` | – | – | Перечисляет кэшированные или разрешённые DICOM-файлы |
| `read_local_metadata` | – | – | Читает заголовок локального файла без пиксельных данных |

### Инструменты пикселей и геометрии (локальные файлы)

| Инструмент | Что делает |
|---|---|
| `render_image` | Рендерит один кадр в PNG и возвращает его вместе с JSON. Оконное преобразование задаётся явными значениями центр/ширина, пресетом (`lung`, `mediastinum`, `soft_tissue`, `abdomen`, `liver`, `bone`, `brain`, `subdural`, `stroke`), окном файла или перцентилями 0.5–99.5. Корректирует неквадратные пиксели и MONOCHROME1, подписывает края направлениями пациента (например, R/L, A/P) |
| `pixel_statistics` | Сообщает минимум, максимум, среднее, стандартное отклонение, перцентили и количество вокселей для кадра или прямоугольной/эллиптической ROI. ROI можно задавать в пикселях или мм. Значения в единицах модальности (HU для КТ), площадь ROI в мм² |
| `measure_distance` | Измеряет вплоскостное расстояние в мм между двумя пикселями и возвращает обе точки в координатах пациента (LPS) |
| `check_geometry` | Группирует файлы в серии и проверяет, можно ли каждую рассматривать как объём. Проблемы сообщаются кодами: `MISSING_SLICES`, `NON_UNIFORM_SPACING`, `DUPLICATE_POSITIONS`, `MIXED_ORIENTATION`, `OBLIQUE`, `SHEARED_STACK`, `INSTANCE_ORDER_MISMATCH` |
| `render_mpr` | Рендерит аксиальный, корональный или сагиттальный срез, переформатированный из серии, прошедшей `check_geometry`. PNG использует истинный мм-аспект и рентгенологическую ориентацию |
| `deidentify` | Записывает деидентифицированные копии в `storage_dir/deidentified` с использованием подмножества Basic Profile. См. [Деидентификация](#деидентификация) |

Каждый результат пиксельных инструментов содержит `input_fingerprint`: SHA-256 хэш декодированных пикселей и геометрии. Он не меняется при смене синтаксиса передачи, и планируемый цикл верификации будет использовать его для привязки результатов к входным данным.

Каждый инструмент несёт MCP-аннотации (`readOnlyHint`, `destructiveHint`, `idempotentHint`), чтобы обвязка могла решить, какие инструменты требуют одобрения.

## Конфигурация

Конфигурационный файл не обязателен. Передавайте узлы и пути как аргументы в конфигурации обвязки; YAML-файл нужен только для расширенных настроек.

### Аргументы

| Аргумент | Значение |
|---|---|
| `--node SPEC` | Добавляет узел. Можно повторять. См. спецификацию узла ниже |
| `--storage-dir DIR` | Локальный кэш для извлечённых файлов и рендеров. По умолчанию `~/.dicom-agent-mcp/cache` |
| `--allow-path DIR` | Дополнительная директория, которую инструменты локальных файлов и пикселей могут читать. Можно повторять |
| `--calling-ae AE` | AE title, который сервер использует для DIMSE. По умолчанию `DICOM_MCP`; зарегистрируйте его в вашем PACS |
| `--config FILE` | Опциональный YAML-файл (см. ниже) |
| `--print-config` | Выводит разрешённые настройки и завершает работу. Удобно для проверки настройки обвязки |

**Спецификация узла:** `name=URL[;option;option…]`

| URL | Тип узла |
|---|---|
| `dimse://AE_TITLE@host:port` | DIMSE (C-FIND, C-GET, C-MOVE, C-STORE) |
| `http://…` или `https://…` | Базовый URL DICOMweb (QIDO-RS, WADO-RS, STOW-RS) |

| Опция | Значение |
|---|---|
| `read-only` | `store`, `move` и `transfer` отказываются писать в этот узел |
| `token-env=VAR` | DICOMweb bearer-токен читается из переменной окружения `VAR` |
| `user=NAME;password-env=VAR` | DICOMweb basic auth; пароль читается из `VAR` |
| `no-verify-tls` | Пропускает проверку TLS-сертификатов (только для тестовых серверов) |
| `transfer-syntax=UID` | Синтаксис передачи, запрашиваемый от WADO-RS. Пусто — дефолт сервера; дефолт `*` сохраняет исходное кодирование |

Примеры:

```text
--node orthanc=dimse://ORTHANC@localhost:4242
--node orthanc-web=http://localhost:8042/dicom-web
--node "azure=https://<workspace>-<service>.dicom.azurehealthcareapis.com/v2;token-env=AZURE_DICOM_TOKEN;read-only"
```

**Секреты никогда не передавайте в аргументах.** Аргументы видны в списке процессов и часто коммитятся в `mcp.json`. Кладите токены и пароли в переменные окружения и передавайте только имя переменной.

Без `--node` сервер всё равно запускается: инструменты локальных файлов и пиксели работают с файлами под разрешёнными путями.

### Переменные окружения

У каждого аргумента есть эквивалент в переменной окружения, что удобно для Docker и CI:

| Переменная | Эквивалент |
|---|---|
| `DICOM_AGENT_MCP_NODES` | `--node`; несколько спецификаций через пробел |
| `DICOM_AGENT_MCP_STORAGE_DIR` | `--storage-dir` |
| `DICOM_AGENT_MCP_ALLOWED_PATHS` | `--allow-path`; несколько путей через `;` в Windows или `:` в других системах |
| `DICOM_AGENT_MCP_CALLING_AE` | `--calling-ae` |
| `DICOM_AGENT_MCP_CONFIG` | `--config` |

### Опциональный YAML-файл (расширенное)

Используйте файл для настроек, у которых нет аргументов: таймауты, `max_results`, `max_volume_voxels`, `deid_key_env` и описания узлов. См. `config.example.yaml`. Если `./dicom-agent-mcp.yaml` существует в рабочей директории, он загружается автоматически. Относительные пути в файле резолвятся относительно директории файла; относительные пути в аргументах и переменных окружения — относительно рабочей директории.

**Приоритет:** конфиг-файл, затем переменные окружения, затем аргументы. Поздние источники переопределяют единичные значения, узлы объединяются по имени (указание `--node` с тем же именем заменяет узел из файла), а разрешённые пути комбинируются.

## Запуск

```powershell
dicom-agent-mcp --node orthanc=dimse://ORTHANC@localhost:4242                                   # stdio
dicom-agent-mcp --node orthanc=dimse://ORTHANC@localhost:4242 --transport streamable-http --port 8000
dicom-agent-mcp --node orthanc=dimse://ORTHANC@localhost:4242 --print-config                    # проверка настроек
```

### VS Code (`.vscode/mcp.json`)

```json
{
  "inputs": [
    { "id": "azureToken", "type": "promptString", "description": "Azure DICOM access token", "password": true }
  ],
  "servers": {
    "dicom": {
      "type": "stdio",
      "command": "${workspaceFolder}/.venv/Scripts/dicom-agent-mcp",
      "args": [
        "--node", "orthanc=dimse://ORTHANC@localhost:4242",
        "--node", "orthanc-web=http://localhost:8042/dicom-web",
        "--node", "azure=https://<workspace>-<service>.dicom.azurehealthcareapis.com/v2;token-env=AZURE_DICOM_TOKEN;read-only",
        "--storage-dir", "${workspaceFolder}/dicom-cache",
        "--allow-path", "${workspaceFolder}/inbox"
      ],
      "env": { "AZURE_DICOM_TOKEN": "${input:azureToken}" }
    }
  }
}
```

### Claude Desktop / Copilot CLI / другие обвязки

```json
{
  "mcpServers": {
    "dicom": {
      "command": "dicom-agent-mcp",
      "args": [
        "--node", "orthanc=dimse://ORTHANC@localhost:4242",
        "--allow-path", "C:/data/dicom-inbox"
      ]
    }
  }
}
```

Используйте абсолютные пути: эти обвязки могут запускать сервер в любой рабочей директории. Чтобы использовать файл вместо аргументов, передайте `"args": ["--config", "C:/path/to/dicom-agent-mcp.yaml"]`.

## Примеры промптов

Эти промпты предполагают три узла: `orthanc` (DIMSE), `orthanc-web` (DICOMweb) и `azure-dicom`, например:

```text
--node orthanc=dimse://ORTHANC@localhost:4242 --node orthanc-web=http://localhost:8042/dicom-web
--node "azure-dicom=https://<workspace>-<service>.dicom.azurehealthcareapis.com/v2;token-env=AZURE_DICOM_TOKEN"
```

После каждого промпта показан инструмент, который агент должен вызвать.

### Узлы и связность

| Промпт | Инструмент |
|---|---|
| «Какие DICOM-узлы настроены, и какие из них read-only?» | `list_nodes` |
| «Проверь, доступны ли `orthanc` и `azure-dicom`.» | `echo` |

### Поиск и метаданные

| Промпт | Инструмент |
|---|---|
| «Найди все КТ-исследования на `orthanc` за последние 30 дней.» | `search` (C-FIND) |
| «Перечисли серии в исследовании `1.2.840…` на `orthanc-web`, с модальностью и количеством изображений.» | `search` (QIDO-RS) |
| «Найди пациентов, чьё имя начинается на `DOE^`.» | `search` на уровне пациента (только узлы DIMSE) |
| «Покажи параметры съёмки серии `1.2.840…`: толщину среза, кВп и пиксельный шаг.» | `get_metadata` |

### Перемещение данных

| Промпт | Инструмент |
|---|---|
| «Скачай грудную КТ-серию с `orthanc` в локальный кэш.» | `retrieve` |
| «Отправь исследование `1.2.840…` с `orthanc` на AE title `WORKSTATION1`.» | `move` (C-MOVE) |
| «Загрузи файлы из `./inbox/case42` в `orthanc-web`.» | `store` (STOW-RS) |
| «Скопируй серию `1.2.840…` с `orthanc` в `azure-dicom`.» | `transfer` (работает через протоколы) |

### Локальные файлы

| Промпт | Инструмент |
|---|---|
| «Какие DICOM-файлы у меня локально?» | `list_local_files` |
| «Прочитай заголовок `./dicom-cache/…/x.dcm`. Он сжат? Какая фотометрическая интерпретация?» | `read_local_metadata` |

### Пиксели и геометрия

| Промпт | Инструмент |
|---|---|
| «Покажи срез 40 этой серии в оконном пресете lung.» | `render_image` (пресет) |
| «Отрендери снова с центром 40 и шириной 400.» | `render_image` (явное окно) |
| «Какое среднее HU в круге 10 мм в центре строка 256, столбец 300?» | `pixel_statistics` (эллипс в мм) |
| «Дай минимум, максимум и 95-й перцентиль для всего кадра.» | `pixel_statistics` |
| «На каком расстоянии в мм пиксель (120, 200) и пиксель (180, 260)?» | `measure_distance` |
| «Можно ли использовать эту серию как 3D-объём? Сообщи о пропущенных срезах или неравномерном шаге.» | `check_geometry` |
| «Покажи средний корональный срез в оконном пресете bone.» | `render_mpr` |
| «Покажи сагиттальный срез 100.» | `render_mpr` |

### Деидентификация

| Промпт | Инструмент |
|---|---|
| «Деидентифицируй скачанное исследование, сдвинь даты и удали приватные теги.» | `deidentify` |
| «Деидентифицируй, но сохрани оригинальные даты и описания серий.» | `deidentify` (`date_mode=keep`, `keep_descriptions`) |

- «Найди последнее КТ для пациента MRN123 на `orthanc`, скачай, проверь геометрию и покажи аксиальный и корональный срезы в оконном пресете soft-tissue.»
- «Измерь среднее HU печени на срезе 60 (круг 15 мм в строке 300, столбце 180) и верни input fingerprint.»
- «Скачай исследование X с `orthanc`, деидентифицируй и загрузи деидентифицированную копию в `azure-dicom`.»

| Промпт | Ожидаемый результат |
|---|---|
| «Загрузи эти файлы в `<узел, отмеченный read_only>`.» | Отказ, потому что узел read-only |
| «Прочитай `C:\Windows\System32\config`.» | Отказ, путь вне песочницы |
| «Отрендери корональный MPR серии с пропущенными срезами.» | Отказ, со списком проблем геометрии |

## Безопасность

- **Песочница путей.** `store`, `list_local_files`, `read_local_metadata` и инструменты пикселей принимают только пути под `storage_dir` или `allowed_paths`.
- **Валидация UID.** UID проверяются перед использованием в путях файлов или URL.
- **Узлы `read_only`.** `store`, `move` и `transfer` отказываются писать в них.
- **Ограничения результатов.** `max_results` ограничивает результаты; усечение сообщается с `truncated: true`.
- **Пиксели в контексте только по запросу.** Сырые массивы пикселей никогда не возвращаются. `render_image` и `render_mpr` отправляют уменьшенный PNG модели; копия сохраняется под `storage_dir/renders`.
- **Ограничение объёма.** `render_mpr` отказывается от серий больше `max_volume_voxels` и от серий, не прошедших `check_geometry`.

### Деидентификация

`deidentify` делает следующее:

- удаляет или очищает идентифицирующие атрибуты;
- удаляет приватные теги и группы оверлеев/кривых;
- заменяет PatientName и PatientID на псевдонимы;
- консистентно перемаппит UID экземпляров;
- по умолчанию сдвигает даты на смещение 1–730 дней на пациента.

Результат фиксируется в `DeidentificationMethodCodeSequence`.

Для получения одних и тех же псевдонимов и UID между запусками задайте секретный ключ в переменной окружения, названной `deid_key_env` (по умолчанию `DICOM_AGENT_MCP_DEID_KEY`). Без ключа каждый вызов использует случайный ключ, и результат сообщает `linkable: false`.

Она **не** удаляет текст, «запечённый» в пикселях; затрагиваемые модальности выдают предупреждение. Это исследовательский инструмент, а не сертифицированное средство деидентификации.

## Архитектура

```
server.py  (FastMCP инструменты)  →  service.py  (маршрутизация, песочница, пагинация)
                                   ├── dimse.py     (pynetdicom SCU)
                                   ├── dicomweb.py  (httpx QIDO/WADO/STOW)
                                   ├── imaging.py   (оконное преобразование, геометрия, статистика ROI, MPR, фингерпринты)
                                   └── deid.py      (подмножество Basic Profile)
```

## Тесты

```powershell
.venv\Scripts\python -m pytest -q
```

Тесты запускают end-to-end проверки против in-process pynetdicom PACS (две AE, чтобы тестировать C-MOVE) и замоканного DICOMweb-сервера. Сеть не требуется. Пиксельные тесты используют синтетическую КТ-серию с известными HU, шагом и позициями.

## Ограничения

- STOW-RS строит весь запрос в памяти, WADO-RS читает весь ответ в память.
- DIMSE `get_metadata` возвращает только атрибуты, которые архив индексирует для C-FIND.
- `retrieve` использует C-GET. Архивы, поддерживающие только C-MOVE, нуждаются в `move` к storage SCP.
- TLS для DIMSE пока не реализован.
- Пиксельные инструменты тестировались только на синтетической КТ и примерах pydicom. Сжатые синтаксисы передачи, enhanced multi-frame объекты и реальные данные пока не тестировались.
- MPR использует выбор ближайшего среза и не ресэмплирует в изотропные воксели.
- Пиксельные инструменты работают с локальными файлами; используйте `retrieve` сначала.
